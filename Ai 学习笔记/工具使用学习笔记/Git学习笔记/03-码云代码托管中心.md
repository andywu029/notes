# pull拉取操作

&emsp;&emsp;拉取操作分为两步`pull = fetch + merge`：

+ `fetch`操作：只是把远程库中的内容下载到本地，但是没有改变本地工作区的文件

```shell
$ git fetch 远程库地址别名 远程分支名
```

![](./images/03/24.png)

+ `merge`操作：把远程代码合并到本地代码中

```shell
$ git merge 远程库地址别名/远程分支名
```

![](./images/03/25.png)

+ `pull`操作：针对没有冲突的情况，不分为上面两个步骤，可以直接使用 `pull` 提取操作

```shell
git pull 远程地址别名 远程分支名
```

![](./images/03/26.png)

# 解决冲突

&emsp;&emsp;在企业中团队协作开发时，当多个人同时修改同一个文件、同一行代码时，就会产生冲突 。只有先推送的那个人才可以正常推送，后面那个人与它出现冲突的代码是没有办法推送的，必须先拉取下来，然后自已手动解决冲突后才可进行推送。

&emsp;&emsp;假设先用一个账号修改了 `README.txt` 的文本，并将该修改 `push` 到远程库。然后另一个账号没有拉取就直接修改了 `README.txt` 的相同行的内容，此时该账号提交远程库就会报错：

![](./images/03/27.png)

&emsp;&emsp;出现冲突后，需要先用 `git pull` 拉取远程代码，然后修改文件，手动解决冲突，保留需要的内容。然后再添加到本地库和远程库：

![](./images/03/28.png)

![](./images/03/29.png)

# SSH 登录

&emsp;&emsp;`windows` 系统自带保存密码功能，如果 mac 没有自带保存密码功能怎么办？`https` 没有记住就帐号，每次登录时都要输入帐号密码很浪费时间。使用 `ssh` 可以避免每次添加用户名密码：

+ 生成密钥

```shell
# 进入当前用户的家目录 ~
$ cd ~

# 如果有.ssh 目录，则删除.ssh 目录
$ rm -rvf .ssh

# 运行命令生成.ssh 密钥目录
$ ssh-keygen -t rsa -C 码云的邮箱地址

#[注意：这里-C 这个参数是大写的 C , 出现光标停留的地方直接按 Enter 键]

# 进入.ssh 目录查看文件列表
$ cd .ssh

# 查看所有目录 与 文件
$ ls -lf
# ./ ../ id_rsa id_rsa.pub

# 查看 id_rsa.pub 文件内容, 复制 id_rsa.pub 文件内容(公钥)
$ cat id_rsa.pub
```

![](./images/03/41.png)

+ 登录码云，点击 用户头像-> 设置

![](./images/03/42.png)

+ 点击 `SSH` 公钥，输入复制的密钥信息

![](./images/03/43.png)

+ 权限验证

![](./images/03/44.png)

+ 回到 `Git Bash` 创建远程 SSH 地址别名
